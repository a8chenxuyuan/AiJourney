# agent1旅行 · 部署文档

> 本文档面向部署/运维人员，按"环境准备 → 安装配置 → 启动验证"三段式组织，
> 覆盖后端（FastAPI）、前端（Vue3）、SQLite 数据库与 Redis 消息队列的完整部署流程。

---

## 0. 架构与组件总览

| 组件 | 技术栈 | 默认端口 | 说明 |
|------|--------|----------|------|
| 前端 | Vue3 + Vite + TypeScript | 5173 | 开发服务器；生产可用 `npm run build` 产物 + Nginx 托管 |
| 后端 API | FastAPI + Uvicorn | 8000 | REST API + SSE 流式推送 |
| Agent Worker | ARQ（Redis 队列） | - | 行程规划/修订后台任务，依赖 Redis |
| 数据库 | SQLite（默认） | - | `backend/agent1travel.db`，可切换 PostgreSQL |
| Redis | Redis 6+ | 6379 | ARQ 任务队列 + 结果存储（必需） |
| Qdrant（可选） | Qdrant 1.12+ | 6333 | RAG 向量检索；未部署时自动降级为内存模式 |

请求链路：浏览器 → 前端(5173) → 后端 API(8000) → 写入 ARQ 队列(Redis) → Agent Worker 消费执行 → 结果落库 → 前端通过 SSE 轮询获取进度。

## 一、环境准备

### 1.1 硬件要求

| 项目 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU | 2 核 | 4 核及以上 |
| 内存 | 4 GB | 8 GB 及以上（Embedding 模型加载约需 1~2 GB） |
| 磁盘 | 5 GB 可用 | 10 GB 可用（含 Embedding 模型缓存约 1.3 GB） |

### 1.2 软件要求

| 软件 | 版本要求 | 用途 |
|------|----------|------|
| Python | 3.10 ~ 3.12（已在 3.12.8 验证） | 后端运行时 |
| Node.js | 18 LTS 及以上 | 前端构建与开发服务器 |
| npm | 随 Node.js 安装 | 前端依赖管理 |
| Redis | 6.0 及以上 | 任务队列（必需，见 1.3） |
| Git | 任意近期版本 | 代码获取 |
| Docker（可选） | 20+ | 一键部署 Redis / Qdrant |

### 1.3 Redis 部署（必需）

Redis 用于 ARQ 任务队列。Windows 环境任选以下一种方案：

**方案 A：Docker（推荐，已安装 Docker Desktop 时）**

```powershell
docker run -d --name agent1-redis --restart unless-stopped -p 6379:6379 redis:7-alpine
docker ps   # 确认容器状态 Up
```

**方案 B：Memurai（Windows 原生 Redis 兼容服务）**

1. 从 https://www.memurai.com 下载并安装 Memurai Developer（免费）；
2. 安装后自动注册 Windows 服务，默认监听 `127.0.0.1:6379`。

**方案 C：WSL2 内安装 Redis**

```bash
# WSL2 (Ubuntu) 内执行
sudo apt update && sudo apt install -y redis-server
sudo service redis-server start
redis-cli ping   # 返回 PONG 即正常
```

**Linux 服务器（生产）**

```bash
sudo apt install -y redis-server
sudo systemctl enable --now redis-server
```

验证 Redis 可用：`redis-cli ping` 返回 `PONG`。

### 1.4 Qdrant 部署（可选）

不部署时，RAG 模块自动降级（远程连接失败回退内存模式、Embedding 不可用时背景知识改由百度百科实时获取），主流程不受影响。如需启用：

```powershell
docker run -d --name agent1-qdrant --restart unless-stopped -p 6333:6333 qdrant/qdrant
```

## 二、安装配置

### 2.1 获取代码

```powershell
git clone <仓库地址> agent1
cd agent1
```

### 2.2 后端安装

```powershell
cd backend

# 创建并激活虚拟环境
python -m venv venv
.\venv\Scripts\activate        # PowerShell；cmd 用 venv\Scripts\activate.bat

# 安装依赖（requirements.txt 已全部 == 锁定版本，保证可重现安装）
pip install -r requirements.txt
```

> 依赖锁定说明：`requirements.txt` 中所有依赖均使用 `==` 精确锁定，
> 与当前验证过的运行环境一致。升级依赖请先在测试环境验证后再修改。

### 2.3 后端配置（.env）

在 `backend/` 目录下创建 `.env` 文件（或复制现有模板修改）。所有配置项由
`backend/app/config.py` 统一管理，支持环境变量覆盖：

| 环境变量 | 默认值 | 必填 | 说明 |
|----------|--------|------|------|
| `APP_NAME` | agent1旅行 | 否 | 应用名称 |
| `ENVIRONMENT` | development | 否 | 运行环境（production 时建议 DEBUG=false） |
| `PORT` | 8000 | 否 | 后端监听端口 |
| `DEBUG` | true | 否 | 调试模式（生产必须 false） |
| `CORS_ORIGINS` | http://localhost:5173,... | 否 | 允许的前端跨域地址，逗号分隔 |
| `DATABASE_URL` | sqlite+aiosqlite:///./agent1travel.db | 否 | 数据库连接串 |
| `JWT_SECRET_KEY` | 内置默认值 | **生产必填** | JWT 签名密钥，生产环境必须改为强随机值 |
| `JWT_ALGORITHM` | HS256 | 否 | JWT 签名算法 |
| `JWT_EXPIRE_MINUTES` | 1440 | 否 | Token 有效期（分钟） |
| `LLM_API_KEY` | 空 | **必填** | 阿里云百炼 API Key |
| `LLM_BASE_URL` | 百炼兼容接口 | 否 | OpenAI 兼容接口地址 |
| `LLM_MODEL_ID` | qwen-max-latest | 否 | 默认模型 ID |
| `LLM_TEMPERATURE` | 0.3 | 否 | LLM 温度参数 |
| `AMAP_API_KEY` | 空 | **必填** | 高德地图 Web 服务 Key（路线/POI 检索） |
| `QDRANT_URL` | http://localhost:6333 | 否 | Qdrant 地址（未部署自动降级） |
| `QDRANT_COLLECTION` | agent1travel_knowledge | 否 | 向量集合名 |
| `EMBEDDING_MODEL_NAME` | BAAI/bge-large-zh-v1.5 | 否 | Embedding 模型（首次运行自动下载） |
| `REDIS_URL` | 空 | **必填** | Redis 连接串，如 `redis://127.0.0.1:6379/1`（用 IP 避免 localhost 解析触发连接超时；用独立 db 编号避免与其他项目共用队列） |
| `CRAWLER_ENABLED` | false | 否 | 是否启用定时爬虫 |
| `PAYMENT_SANDBOX` | true | 否 | 支付沙箱开关 |

最小可运行 `.env` 示例：

```ini
LLM_API_KEY=sk-xxxxxxxxxxxxxxxx
AMAP_API_KEY=你的高德Key
REDIS_URL=redis://127.0.0.1:6379/1
JWT_SECRET_KEY=请替换为强随机字符串
DEBUG=false
```

### 2.4 前端安装

```powershell
cd frontend
npm install
```

如需修改后端地址，编辑 `frontend/src/api/`（或 `.env` 中 `VITE_API_BASE_URL`，以项目内实际配置为准）。

## 三、启动验证

### 3.1 启动服务（开发/单机部署，需开启 3 个终端）

**终端 1：后端 API**

```powershell
cd backend
.\venv\Scripts\python.exe run.py
```

启动成功标志：`Uvicorn running on http://0.0.0.0:8000`。
首次启动会自动建表并为旧库补建缺失索引（幂等，可重复执行）。

**终端 2：Agent Worker（任务队列消费者）**

```powershell
cd backend
.\venv\Scripts\python.exe worker.py
```

启动成功标志：Worker 完成注册并开始监听队列。
> 注意：不启动 Worker 时，行程规划请求会入队但不会被消费。

**终端 3：前端**

```powershell
cd frontend
npm run dev
```

启动成功标志：`Local: http://localhost:5173/`。

### 3.2 验证清单

按顺序逐项验证：

| # | 验证项 | 操作 | 预期结果 |
|---|--------|------|----------|
| 1 | Redis | `redis-cli ping` | 返回 PONG |
| 2 | 后端存活 | 浏览器打开 `http://localhost:8000/api/health` | 返回 `{"status":"ok",...}` |
| 3 | Worker 就绪 | 终端 2 无报错并监听队列 | 无连接异常日志 |
| 4 | 前端加载 | 打开 `http://localhost:5173` | 页面正常渲染 |
| 5 | 注册/登录 | 前端注册账号并登录 | 成功进入主页 |
| 6 | 创建行程 | 提交一次旅行规划 | SSE 实时显示 Agent 进度，最终生成行程 |
| 7 | 反馈修订 | 在结果页提交修改意见并重新生成 | 生成新版本，版本历史可见 |
| 8 | 日志落盘 | 查看 `backend/logs/` | 有按天滚动的 `app_YYYY-MM-DD.log`；错误另存 `error_*.log` |

### 3.3 生产部署补充说明

- **停止服务**：各终端 `Ctrl+C`；Docker 部署用 `docker stop agent1-redis`。
- **数据备份**：定期备份 `backend/agent1travel.db`（低峰期复制文件即可）。
- **日志**：`backend/logs/` 按天滚动、保留 30 天，磁盘紧张时调整
  `backend/app/utils/logger.py` 中的 `retention` 参数。
- **安全**：生产环境务必修改 `JWT_SECRET_KEY`、设置 `DEBUG=false`、
  将 `CORS_ORIGINS` 收敛为真实前端域名；Nginx 反向代理时为 SSE 路由
  （`/api/agent/trip/*/stream`）关闭缓冲（`proxy_buffering off`）并将读超时调大（≥10 分钟）。
- **多实例扩展**：如横向扩容多个后端实例，Redis 与数据库天然共享；
  但进程内 revision 并发锁仅单进程有效，需改用 Redis 分布式锁（见《系统适配说明》已知限制）。

## 四、Docker Compose 一键部署（可选）

项目根目录的 `docker-compose.yml` 编排了完整技术栈：
**Qdrant（向量库）+ Redis（任务队列）+ backend（API）+ worker（ARQ 消费者）+ frontend（Nginx 托管前端并反代 API）**。

### 4.1 首次部署

```powershell
# 在项目根目录（Windows 下 Docker 在 WSL2 内，路径可写为 /mnt/d/...）
docker compose up -d --build
```

构建说明：
- `backend/Dockerfile`：Python 3.12-slim 基础镜像，先装 CPU 版 torch（官方 CPU 源）再装
  requirements.txt，backend 与 worker 共用同一镜像、仅启动命令不同；
- `frontend/Dockerfile`：两阶段构建（Node 编译 + Nginx 托管），构建时注入
  `VITE_API_BASE_URL=/api`，前端与后端同源，无跨域问题；
- 敏感配置经 `env_file: backend/.env` 注入容器，不会写入镜像层；
- 容器内基础设施地址由 `environment` 覆盖（Qdrant→`http://qdrant:6333`、
  Redis→`redis://redis:6379/1`、SQLite→`/app/data/agent1travel.db`），
  pydantic-settings 中环境变量优先于 .env 文件。

### 4.2 Embedding 模型缓存

容器内 RAG 需要 bge-small-zh-v1.5 模型。compose 默认只读挂载宿主机 HuggingFace 缓存
（WSL 路径 `/mnt/c/Users/Administrator/.cache/huggingface`）；若缓存位置不同，用环境变量覆盖：

```powershell
HF_CACHE_DIR=/path/to/huggingface docker compose up -d
```

### 4.3 端口与数据卷

| 服务 | 宿主机端口 | 数据卷 |
|------|-----------|--------|
| frontend (Nginx) | **8081**（浏览器入口；8080 常被其他项目占用，如遇冲突可自行调整） | - |
| backend | 8000（也可直连） | `backend_data`（SQLite） |
| qdrant | 6333 / 6334 | `qdrant_data`（攻略向量，重建容器不丢） |
| redis | 不映射（宿主机 6379 已被本地 Redis 占用） | `redis_data`（AOF 队列持久化） |
| worker | - | 与 backend 共用 `backend_data` |

### 4.4 常用运维命令

```powershell
docker compose ps                    # 状态
docker compose logs -f backend worker # 跟日志
docker compose restart backend       # 重启单服务
docker compose down                  # 停止（保留数据卷；加 -v 连数据一起删）
```

> 开发态与容器态可并存：本地开发用 `python run.py` + `python worker.py` + `npm run dev`
> （复用容器化的 Qdrant/Redis），演示/部署用 `docker compose up -d`。
> 注意两者端口冲突：容器 backend 占 8000，需先停本地后端再 `up`。
