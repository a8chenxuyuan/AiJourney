# agent1 架构升级方案（最终版 v1.0）

> 日期：2026-10-22
> 依据：AgentScope Java 2.0 能力对标 + 合同卫士七层结构规范
> 原则：**接口先行、机制后长、一切皆插件、触发式生长**；每批独立可验证、可单独 commit；迁移全程保留 re-export 垫片，对外 import 路径不变，表结构只增不改。

---

## 一、背景与目标

对照 AgentScope 2.0（Harness 工程化 / 企业级分布式 / 底层框架重构），agent1 的编排骨架（LangGraph 批次执行 + SSE + arq 队列）底子完好，真实差距集中在三处"长跑能力"：

1. **上下文无管理**：planner 一次吃全量景点/酒店/餐厅 JSON，多城翻倍，任务越复杂 prompt 越胖
2. **状态不可恢复**：worker 崩溃 = 在途规划任务丢失，只能从头重跑（曾发生残留 worker 竞争消费队列事故）
3. **HITL 是占位**：human_in_the_loop 自动放行，产品级替代方案"反馈后 regenerate 重跑全图"浪费已完成批次

同时结构上按合同卫士七层规范对齐，补齐 agentkit 框架层，使后续能力都以"插件/Layer"方式生长。

## 二、目标架构：七层单向依赖

```
依赖方向（只允许上层 import 下层，禁止反向）：

接口层（api/routes、tasks 薄壳）
    ↓
planning（业务编排层）
    ↓
travel（行程领域层）
    ↓
agentkit（Agent 框架层，零业务感知）
    ↓
rag（检索底座）   llm（模型调用层）
    ↘               ↙
      core（基建层）
```

## 三、agentkit 框架层协议（六条铁律）

| 协议 | 内容 | 对应批次 |
|---|---|---|
| **事件总线** | `agentkit/events.py` 是唯一事件出口。事件类型：`node_start / node_end / log / token_delta / state / approval_required / done / failed`。SSE 推送、node_attempt 落库、trace 日志均为同一事件流的订阅方，禁止平行推送 | 批次 2 |
| **上下文装配** | `agentkit/context/manager.py` 的 `assemble(plan_id, agent_name, layers)` 是唯一入口。可注册 Layer：MemoryLayer（用户记忆）、SkillLayer（技能）、RagLayer（攻略上下文）、ArtifactLayer（工具结果摘要）。节点禁止自行拼 prompt 字符串 | 批次 3 |
| **断点快照** | `agentkit/executor.py` 每批次 merge 完成后触发 `checkpoint_hook(batch_index, state_snapshot)`；启动时支持 `start_batch` 续跑。快照剔除 messages/logs 大字段 | 批次 4 |
| **审批协议** | `agentkit/approval.py`：节点可声明暂停点 → 写 checkpoint + 状态置 pending_approval + 总线推 approval_required → 外部 approve 后从暂停批次 resume。三态：auto_approve / require_approval / reject | 批次 5 |
| **工具注册** | 所有工具经 `@register_tool` 注册到 TOOL_REGISTRY，权限三态 ALLOW/APPROVE/DENY 由配置覆盖，APPROVE 钩子接审批协议。禁止硬编码工具列表 | 批次 6 |
| **技能仓库** | `agentkit/skills.py` 运行时：`workspace/skills/*.md` + index.json（tags 匹配）按需加载注入。沉淀入口先半自动（放 md 文件即生效），自动沉淀只留协议插槽 | 批次 6 |

## 四、Prompt 治理（三步走）

| 阶段 | 形态 | 说明 |
|---|---|---|
| 现状 | `agents/prompts.py` 单文件 400+ 行大杂烩 | 已集中，但按使用方拆分与装配方式不达标 |
| 批次 1 | `planning/prompts/` 一 agent 一文件 | 对齐合同卫士 review/prompts/ 目录约定；对外保留 `agents/prompts.py` 垫片 re-export |
| 批次 6 | `workspace/prompts/*.md` 外置 | prompt_loader 启动加载+缓存，改 prompt 改文件即生效；节点经 assemble() 拿成品，禁止 `.format()` 手拼 |

## 五、功能里程碑详情

| 步骤 | 内容 | 涉及文件 |

### M2 断点续跑 + 执行记录（批次 2 + 4）

| 步骤 | 内容 | 涉及文件 |
|---|---|---|
| 1 | attempt 订阅事件流落库（批次 2 随总线完成） | node_attempt 表【新】、events 订阅者 |

### M3 真 HITL + Token 流（批次 5）

| 步骤 | 内容 | 涉及文件 |
|---|---|---|
| 1 | HITL 实装：预算超阈值（travel/budget.py 判定）时 human_in_the_loop 不再自动放行——写 checkpoint、状态 pending_approval、总线推 approval_required、任务正常返回暂停 | planning/agents/human_in_the_loop.py、travel/budget.py、agentkit/approval.py |

| 4 | 前端确认卡：收到 approval_required 弹预算确认卡（超支明细 + 通过/驳回） | frontend views/trip/Planning.vue |

**验证**：构造超预算请求 → 停在 pending_approval → 前端弹卡 → approve 后从暂停点继续（不重跑前序批次）→ reject 状态闭环。

## 八、明确不做

- Plan Mode（业务行程规划 ≠ 任务执行规划，无对应场景）
- 多租户 org 隔离、安全沙箱（无可信代码执行场景）
- 消息模型 ContentBlock 统一（现有 Pydantic schema 够用）
- 子智能体跨进程 spawn（多城保持进程内 gather，只留 scoped state 规范接口）
- AgentScope Service 式平台层（Team/Workflow/Endpoint/控制台，单体产品不需要）

## 九、最终验收标准

1. `check.ps1` 五步全过（ruff / 七层依赖 / 导入+表数 / ESLint / build）
2. 冒烟：health + 登录 + 规划入队 + 断点续跑 + 审批恢复 五条用例全过
3. 全仓无旧路径残留（垫片删除后）、无平行事件通道、无手拼 prompt
4. 每批次一个 commit，提交由用户自行执行
