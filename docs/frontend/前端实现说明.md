# agent1旅行 — 前端实现说明

## 1. 技术栈总览

前端采用 **Vue 3 + TypeScript + Vite** 作为基础架构，配合 **Ant Design Vue** 作为 UI 组件库，使用 **Vue Router** 做路由管理，**Pinia** 做全局状态管理，**Axios** 处理 HTTP 请求，**高德 JSAPI Loader** 加载地图，**ECharts** 展示预算图表，**html2canvas + jsPDF** 实现导出功能。

| 技术 | 作用 |
|------|------|
| Vue 3 | 前端框架，组合式 API 组织逻辑 |
| TypeScript | 类型约束，提升代码可维护性 |
| Vite | 构建工具，开发热更新、生产打包 |
| Ant Design Vue | UI 组件库（表单、表格、按钮、Modal、Timeline 等） |
| Vue Router | 页面路由跳转，支持动态参数 |
| Pinia | 全局状态管理（用户信息、当前行程、规划状态） |
| Axios | 封装 HTTP 请求，统一拦截器和错误处理 |
| 高德 JSAPI Loader | 异步加载高德地图 JSAPI，绘制地图、Marker、路线 |
| ECharts | 预算饼图、天气趋势图 |
| html2canvas | 把 DOM 区域转成 Canvas，用于导出图片 |
| jsPDF | 把 Canvas 转成 PDF 下载 |

## 3. 各文件作用与技术对应关系

### 3.1 入口与配置层

| 文件 | 对应技术 | 作用 |
|------|----------|------|
| `main.ts` | Vue 3 | 创建 Vue 应用实例，注册 Ant Design Vue、Pinia、Router，挂载到 DOM |
| `App.vue` | Vue 3 | 根组件，包含全局布局（Header + Sider + Content），控制登录/未登录状态展示 |
| `router/index.ts` | Vue Router | 定义所有路由，配置路由守卫，未登录用户跳转到登录页 |
| `vite.config.ts` | Vite | 配置开发服务器、代理到后端、路径别名、插件 |

### 3.2 状态管理层（Pinia）

| 文件 | 对应技术 | 作用 |
|------|----------|------|
| `stores/user.ts` | Pinia + JWT | 管理登录态、Token、用户信息、登录/登出方法 |
| `stores/trip.ts` | Pinia | 管理当前行程请求、结果、候选方案、选中的方案索引 |
| `stores/planning.ts` | Pinia + SSE | 接收并缓存 SSE 推送的 Agent 节点执行日志、当前步骤 |

### 3.3 服务层（Axios + SSE）

| 文件 | 对应技术 | 作用 |
|------|----------|------|
| `services/api.ts` | Axios | 创建 axios 实例，配置 baseURL、超时、请求拦截器（自动加 JWT）、响应拦截器（统一错误处理） |
| `services/auth.ts` | Axios | 封装 `/api/auth/register`、`/api/auth/login`、`/api/auth/me` |
| `services/trip.ts` | Axios | 封装 `/api/trip/plan`、查询、重算、反馈等接口 |
| `services/map.ts` | Axios | 封装地图 POI、天气、路线接口 |
| `services/payment.ts` | Axios | 封装支付创建、查询、回调接口 |
| `services/sse.ts` | EventSource | 封装 SSE 连接，监听 `/api/trip/{plan_id}/stream`，把事件推给 `planningStore` |

## 4. 整体流程实现

### 4.1 登录与认证流程

```
用户打开 /login
  → 填写用户名密码
  → services/auth.ts 调用 POST /api/auth/login
  → 后端返回 JWT
  → stores/user.ts 保存 token
  → localStorage 同步保存 token
  → 路由守卫放行，进入 Home
```

### 4.2 生成旅行计划流程

```
用户在 Home.vue 填写表单
  → TripForm.vue 校验并组装 TripRequest
  → services/trip.ts 调用 POST /api/trip/plan
  → 后端返回 plan_id
  → 前端跳转 /planning/:id
  → Planning.vue 加载
      ├─ 调用 GET /api/trip/{plan_id} 获取当前状态
      └─ 通过 services/sse.ts 建立 SSE 连接 /api/trip/{plan_id}/stream
  → 后端 LangGraph 每执行一个节点，推送事件到前端
  → planningStore 更新节点日志
  → AgentTimeline.vue / ToolCallLog.vue 实时渲染
  → 当状态变为 completed，前端跳转 /result/:id
  → Result.vue 从 stores/trip.ts 或接口加载 TripPlan
  → 初始化高德地图、渲染每日行程、预算图表、天气卡片
```

### 4.3 人机协同流程

```
LangGraph 执行到 HumanInLoopNode
  → 后端通过 SSE 推送 `human_interrupt` 事件
  → HumanConfirmModal.vue 弹出
  → 用户选择后，调用 POST /api/trip/{plan_id}/human_decision
  → 后端恢复图执行
  → 前端继续接收 SSE 事件
```

### 4.4 调整景点后重算流程

```
用户在 Result.vue 拖拽景点调整顺序
  → stores/trip.ts 更新本地景点顺序
  → 调用 POST /api/trip/{plan_id}/recalculate
  → 后端加载已保存 State，重新执行 RouteAgent + PlannerAgent
  → 返回新的 TripPlan
  → 前端刷新地图路线和每日行程
```

### 4.5 支付流程（沙箱）

```
用户在 Result.vue 点击「预订并支付」
  → 调用 POST /api/payment/create
  → 后端创建 Order，返回订单信息和沙箱支付参数
  → 前端跳转 /payment/:orderId
  → Payment.vue 展示订单金额和模拟支付按钮
  → 用户点击支付，调用 POST /api/payment/notify（或等待后端回调）
  → 后端更新订单状态为 paid
  → 前端展示支付成功
```

### 4.6 导出流程

```
用户在 Result.vue 点击「导出 PNG/PDF/Markdown」
  → export.ts 根据类型执行不同逻辑
      ├─ PNG：html2canvas 捕获 .export-area → 下载图片
      ├─ PDF：html2canvas → jsPDF 分页拼接 → 下载 PDF
      └─ Markdown：把 TripPlan JSON 转为 Markdown 文本 → 下载 .md 文件
```

## 5. 关键技术点说明

### 5.1 JWT 鉴权
- 登录后 Token 存 `localStorage` 和 `userStore`；
- Axios 请求拦截器自动在 Header 中加入 `Authorization: Bearer <token>`；
- 后端校验失败返回 401，响应拦截器清除 Token 并跳转登录页。

### 5.2 SSE 实时推送
- 使用原生 `EventSource` 或 `@microsoft/fetch-event-source`；
- 后端推送事件格式为 JSON，前端按事件类型更新不同 UI；
- 页面离开时关闭连接，避免资源泄漏。

### 5.3 地图集成
- 通过 `@amap/amap-jsapi-loader` 异步加载高德地图；
- 景点坐标用 `AMap.Marker` 标记，点击弹出 `AMap.InfoWindow`；
- 每日路线用 `AMap.Polyline` 绘制，不同天用不同颜色区分。

### 5.4 状态共享
- 行程结果在 `tripStore` 中全局共享，避免页面间通过 URL 传大量数据；
- 用户偏好和历史行程进入 Profile 时再从接口加载。

## 6. 与后端的协作边界

| 前端职责 | 后端职责 |
|----------|----------|
| 收集用户输入、展示表单 | 校验请求、调用 Agent |
| 接收 SSE 事件并渲染 | 执行 LangGraph 并推送事件 |
| 调用地图 JSAPI 展示 | 提供 POI/天气/路线数据 |
| 用户认证状态管理 | JWT 签发与校验 |
| 导出 PNG/PDF/Markdown | 提供结构化 TripPlan 数据 |
| 展示沙箱支付页面 | 创建订单、处理回调 |

前端不直接调用 LLM 或向量库，所有 AI 能力都通过后端 API 获取。
